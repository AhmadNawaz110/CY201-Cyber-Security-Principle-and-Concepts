1.1 Definition & Evolution of IoT

What is IoT?

A network of physical objects—"things"—embedded with sensors, software, and other technologies for the purpose of connecting and exchanging data with other devices and systems over the internet.

Timeline

  • 1980s: Carnegie Mellon Coke Machine (First IP-connected device).
  • 1999: Kevin Ashton coins term "Internet of Things".
  • 2008: First "IoT" conference; IPv6 adoption.
  • 2010s-Present: Smart Home, Smart Cities, IIoT explosion.

1.2 IoT Architecture (The 3-Layer Model)

Perception:

Sensors (Temp, GPS), Actuators, RFID tags. Collects data.

Network:

Gateways, Routers, Protocols (MQTT, CoAP, Zigbee). Transmits data.

Application:

Cloud Storage, Analytics, User Interface. Uses data.

1.3 IoT Ecosystems: Smart Home, IIoT, Healthcare

Consumer IoT

  • Smart Thermostats
  • Connected Appliances
  • Wearables
  • Smart Speakers

Risk: Data privacy, weak security, scale of devices.

Industrial IoT (IIoT)

  • Manufacturing Robots
  • SCADA/PLC Integration
  • Predictive Maintenance
  • Supply Chain Tracking

Risk: Safety of life, high cost downtime, legacy protocols.

Healthcare IoT

  • Insulin Pumps
  • Patient Monitors
  • Smart MRI
  • Telehealth Robots

Risk: Patient safety (Life Critical), HIPAA data.

1.4 Benefits vs. Challenges

Benefits

Efficiency: Automated processes reduce labor costs.

Real-time Data: Immediate decision making.

Cost Savings: Predictive maintenance prevents failure.

Challenges

Security Fragmentation: No standard OS.

Update Mechanism: Difficult to patch.

Lifecycle: Devices outlast support.

Privacy: Surveillance capitalism.

2.1 Common IoT Vulnerabilities

  • 1. Weak Authentication: Default credentials (admin/admin) remain the #1 issue.
  • 2. Insecure Network Services: Open ports (Telnet 23, HTTP 80) exposed to WAN.
  • 3. Lack of Encryption: Data transmitted in plain text.
  • 4. Lack of Update Mechanism: Firmware cannot be patched remotely.
  • 5. Physical Hardening: Debug ports (UART/JTAG) left exposed.

2.2 Botnets: The Mirai Case Study

How Mirai Works

  1. Scanning: Bot scans internet for IoT devices on Telnet (Port 23).
  2. Brute Force: Tries 60 default username/password combos.
  3. Infection: Downloads malware, wipes itself from disk (RAM-only).
  4. Attack: C2 commands device to flood target with traffic.

2.3 Man-in-the-Middle (MITM) Attacks

Scenario: ARP Spoofing

An attacker convinces the Smart Lock that the Attacker is the Router, and the Phone that the Attacker is the Lock.

Defense: Use Mutual TLS (mTLS). The Device must verify the Server's certificate, and the Server must verify the Device's certificate.

2.4 Physical Attacks & Firmware Tampering

JTAG / UART Access

Many devices have debugging pins exposed on the PCB. Attaching wires allows dumping the firmware to find encryption keys.

Bus Sniffing

Connecting to I2C or SPI buses to read sensor data in transit before encryption.

2.5 Real-World Breaches

Treasury Casino (2022)

Hackers accessed smart cameras to spy on operations, gaining access to the backend database via lateral movement.

Cause: Default passwords on DVRs.

St. Jude Medical Cardiac Devices

Vulnerabilities found in pacemakers that allowed attackers to drain battery or alter pacing.

Cause: Lack of proper authentication protocols.

3.3 Secure Protocols: MQTT vs CoAP

MQTT (Publish/Subscribe)

Transport: TCP

Best For: Unstable networks where message delivery is critical (e.g., Smart Metering).

Security: TLS (Port 8883), Client Certificates.

CoAP (Request/Response)

Transport: UDP

Best For: Constrained devices needing low latency (e.g., Light Switch).

Security: DTLS (Datagram TLS).

3.4 Hardware Root of Trust (HSM/TPM)

Software keys can be dumped from memory. A Hardware Security Module (HSM) or TPM (Trusted Platform Module) holds keys in hardware.

  • Secure Boot: Verifies firmware integrity before execution.
  • Key Storage: Keys never leave the chip.

3.5 Secure Update Mechanism

Safe Firmware Update Flow

  1. 1. Sign
    Vendor signs firmware with Private Key.
  2. 2. Transfer
    Encrypted transfer (HTTPS) to device.
  3. 3. Verify
    Device uses embedded Public Key to verify signature.
  4. 4. Flash
    If valid, update applied. If invalid, reject.

4.4 Privacy Compliance (GDPR/CCPA)

Right to be Forgotten

In Smart Homes (Alexa/Cameras), users can demand their data be deleted. This complicates IoT architecture because:

  • Data is often distributed (Edge + Cloud).
  • Logs are immutable.
  • Raw sensor data might be mixed with other data.
Analyst Tip: Design data retention policies into the database schema from day one.

4.5 Module 4 Scenario

Scenario: The Rogue Wi-Fi Extender

An employee brings a personal Wi-Fi extender from home and plugs it into the LAN port.

Impact: It bypasses the corporate firewall, creating an open backdoor.

Remediation:

  1. Port Security: Limit MAC addresses per port on the switch.
  2. NAC: Implement Network Access Control to profile unknown devices.

5.1 Challenges in IoT Forensics

Volatile Memory

Most IoT data lives in RAM. Powering off the device wipes all evidence.

Proprietary Formats

File systems (YAFFS2, JFFS2) are not supported by standard tools like EnCase.

No Logs

Devices often lack internal storage. Logs are streamed to cloud and lost if network is cut.

5.2 Containment: Shunning vs. Isolation

Network Shunning (Blacklisting)

Using Firewall ACLs to drop packets from a specific device MAC/IP.

Pros: Instant. Cons: Device might just change IP.

Physical Isolation

Disable the physical switch port or VLAN.

Pros: Total containment. Cons: Service disruption.

5.4 Eradication & Recovery

Eradication

  • Reset device to factory defaults (if possible).
  • Flash firmware from a trusted source.
  • Change default credentials immediately.

Recovery

  • Restore secure configuration.
  • Monitor logs for recurrence.
  • Conduct Root Cause Analysis (RCA).

6.3 ETSI EN 303 645 (Consumer IoT)

The Baseline Standard

A European standard adopted globally for consumer devices.

  • Requirement 1: No universal default passwords.
  • Requirement 2: Implement a means to manage vulnerabilities (updates).
  • Requirement 3: Keep software updated.
  • Requirement 4: Securely store sensitive data.
  • Requirement 5: Communicate securely.

7.3 IIoT Case Study: Water Treatment Plant

The Attack Vector

Hackers gained access to a water plant via TeamViewer installed on an operator's Windows PC.

They used the TeamViewer connection to change the chemical mix levels.

Lesson: Never expose Remote Desktop (RDP) or VNC directly to the internet on OT networks. Use VPNs or Zero Trust.
