1. Privacy Concepts & Security Foundations

Learning Objectives

  • Define core security principles (CIA Triad + Non-repudiation)
  • Understand privacy models across data lifecycle
  • Compare privacy vs. security concepts
  • Identify regulatory context affecting security design

The CIA Triad

Confidentiality

Protection of information from unauthorized access

  • Encryption
  • Access controls
  • Authentication

Integrity

Assurance of data accuracy and completeness

  • Hashing
  • Digital signatures
  • Checksums

Availability

Timely and reliable access to information and resources

  • Redundancy
  • Failover mechanisms
  • DDoS protection

Non-repudiation is the assurance that someone cannot deny the validity of something.

Critical for:

  • Financial transactions
  • Legal communications
  • Audit trails

Achieved through:

  • Digital signatures
  • Cryptographic receipts
  • Timestamps

Privacy Models: Data Lifecycle

Privacy vs. Security Comparison

Aspect Privacy Security
Focus Individual rights System protection
Primary Concern Personal data handling Threat mitigation
Approach Policy-driven Technical controls
Example GDPR compliance Firewall implementation

Regulatory Context

General Data Protection Regulation (GDPR)

  • Scope: EU citizens' data
  • Key requirements:
    • Consent
    • Right to be forgotten
    • Breach notification (72 hours)
    • Data protection by design
  • Fines: Up to 4% of global annual revenue or €20 million

Health Insurance Portability and Accountability Act (HIPAA)

  • Scope: Protected health information (PHI)
  • Key requirements:
    • Administrative safeguards
    • Physical safeguards
    • Technical safeguards
  • Fines: Up to $1.5 million per year per violation

Other Important Regulations

  • CCPA: California Consumer Privacy Act
  • PCI DSS: Payment Card Industry Data Security Standard
  • SOX: Sarbanes-Oxley Act
  • FISMA: Federal Information Security Management Act

Instructor Note:

Explain how these three principles form the foundation of security. Ask students: "What happens if one of these pillars fails?"

Key Takeaways

  1. CIA Triad forms the foundation of security principles
  2. Privacy considerations extend across the entire data lifecycle
  3. Privacy and security are complementary but distinct concepts
  4. Regulatory requirements drive many security implementations

2. Principles of Cryptography

Learning Objectives

  • Differentiate symmetric vs. asymmetric cryptography
  • Understand key management challenges
  • Explain Shannon's principles of confusion and diffusion
  • Identify common cryptographic algorithms and their use cases

Symmetric vs. Asymmetric Cryptography

Symmetric Cryptography

  • Single key for encryption and decryption
  • Faster processing
  • Key distribution challenges
  • Examples: AES, DES, 3DES

Asymmetric Cryptography

  • Public/private key pair
  • Slower processing
  • Easier key distribution
  • Examples: RSA, ECC, Diffie-Hellman

Key Management Challenges

Shannon's Principles

Confusion

Obscuring the relationship between ciphertext and key

  • Achieved through substitution
  • Makes key discovery difficult
  • Example: S-boxes in AES

Diffusion

Spreading the influence of plaintext across ciphertext

  • Achieved through permutation/transposition
  • Makes statistical analysis difficult
  • Example: MixColumns in AES

Advanced Encryption Standard (AES)

  • Block cipher with 128-bit blocks
  • Key sizes: 128, 192, 256 bits
  • Rounds: 10, 12, 14 respectively
  • Operations: SubBytes, ShiftRows, MixColumns, AddRoundKey

Rivest-Shamir-Adleman (RSA)

  • Based on factorization difficulty
  • Key generation: Choose two large primes p and q
  • Public key: (n = p×q, e)
  • Private key: (n = p×q, d)
  • Security relies on difficulty of factoring n

Elliptic Curve Cryptography (ECC)

  • Advantages:
    • Smaller key sizes for equivalent security
    • Faster computations
    • Lower power consumption
  • Applications:
    • Mobile devices
    • IoT
    • Blockchain
  • Security Comparison:
    • ECC 256-bit ≈ RSA 3072-bit
    • ECC 384-bit ≈ RSA 7680-bit

Hash Functions

  • Properties:
    • Deterministic
    • Quick to compute
    • Irreversible (pre-image resistance)
    • Collision resistant
  • Common Algorithms:
    • SHA-2 family (SHA-256, SHA-512)
    • SHA-3
    • MD5 (broken, not recommended)
    • SHA-1 (deprecated)
  • Applications:
    • Password storage
    • Data integrity verification
    • Digital signatures
    • Blockchain

Real-World Cryptographic Analogies

Symmetric Key

Physical lock and key (same key opens and locks)

Asymmetric Key

P.O. box (public key for deposit, private key for retrieval)

Hash Function

Fingerprint (unique identifier of data)

Digital Signature

Sealed envelope with unique wax stamp

Key Takeaways

  1. Symmetric cryptography offers speed but key distribution challenges
  2. Asymmetric cryptography solves key distribution but requires more resources
  3. Shannon's principles of confusion and diffusion underpin modern ciphers
  4. Algorithm selection depends on security requirements, performance, and use case

3. Public Key Infrastructure (PKI)

Learning Objectives

  • Understand PKI components and their roles
  • Explain certificate lifecycle management
  • Analyze TLS/SSL handshake process
  • Identify common PKI vulnerabilities and misconfigurations

PKI Components Overview

Certificate Authority (CA) Hierarchy

X.509 Certificate Fields

  • Version: X.509 version (v3 most common)
  • Serial Number: Unique identifier issued by CA
  • Signature Algorithm: Algorithm used by CA to sign certificate
  • Issuer: Name of CA that issued certificate
  • Validity Period: Not before and not after dates
  • Subject: Identity of certificate owner
  • Public Key: Subject's public key
  • Extensions: Additional constraints and properties

TLS/SSL Handshake Process

TLS 1.3 Improvements

TLS 1.2

  • 2-RTT handshake (full)
  • Supports weak algorithms
  • Optional forward secrecy
  • Partial handshake encryption

TLS 1.3

  • 1-RTT handshake (full)
  • 0-RTT (with resumption)
  • Removed weak algorithms
  • Mandatory forward secrecy
  • Encrypted handshake

Common PKI Vulnerabilities

  • Weak Certificate Practices:
    • Insufficient key lengths
    • Overly long validity periods
    • Incomplete certificate chains
  • Implementation Flaws:
    • Improper certificate validation
    • Lack of revocation checking
    • Insecure algorithm configurations
  • Infrastructure Issues:
    • Compromised CAs
    • Poor key protection
    • Inadequate certificate inventory

2011 Dutch CA Compromise

  • Incident: 2011 compromise of Dutch CA DigiNotar
  • Impact: Fraudulent certificates for major domains (Google, CIA, etc.)
  • Attack Vector: Malware on CA servers
  • Consequences:
    • Browser vendors revoked DigiNotar certificates
    • Company declared bankrupt
    • Dutch government services disrupted
  • Lessons Learned:
    • CA security is critical
    • Need for certificate transparency
    • Importance of rapid response

Key Takeaways

  1. PKI provides the framework for establishing trust in digital communications
  2. Certificate lifecycle management is as important as the certificates themselves
  3. TLS 1.3 significantly improves security and performance over previous versions
  4. PKI security requires attention to both technical implementation and operational processes

4. Cryptographic Attacks & Attack Vectors

Learning Objectives

  • Categorize different types of cryptographic attacks
  • Analyze attack methodologies and their impact
  • Understand real-world attack scenarios
  • Identify mitigation strategies for each attack type

Attack Classification Framework

Man-in-the-Middle (MITM) Attacks

Replay Attacks

Side-Channel Attacks

Attack Method

  • Force use of weaker cryptographic protocols
  • Exploit backward compatibility

Examples

  • POODLE: SSL 3.0 vulnerability
  • FREAK: Export-grade RSA
  • Logjam: Diffie-Hellman downgrade

Mitigation

  • Disable outdated protocols
  • Implement protocol negotiation safeguards
  • Forward secrecy

Vulnerability

  • Buffer over-read in OpenSSL TLS heartbeat extension
  • Exposure of up to 64KB of server memory per request

Information Exposed

  • Private keys
  • Session tokens
  • User credentials

Lessons

  • Critical importance of memory safety
  • Need for thorough code review
  • Value of cryptographic agility

Attack-Defense Mapping

Attack Type Defense Mechanism
Brute Force Strong keys, rate limiting
MITM Certificate verification, pinning
Replay Nonces, timestamps
Side-channel Constant-time implementation
Downgrade Disable weak protocols
Quantum Post-quantum algorithms

Key Takeaways

  1. Cryptographic systems face threats from both mathematical analysis and implementation flaws
  2. Defense in depth is essential—no single mitigation is sufficient
  3. Implementation details often matter more than theoretical algorithm strength
  4. Future-proofing requires consideration of emerging threats like quantum computing

Network Security Controls by Layer

Common Network Attacks

Layer 2 Attacks

  • MAC flooding
  • ARP spoofing
  • VLAN hopping

Layer 3 Attacks

  • IP spoofing
  • ICMP attacks
  • Routing attacks

Layer 4 Attacks

  • SYN flood
  • UDP amplification
  • Session hijacking

Layer 7 Attacks

  • HTTP floods
  • Application exploits
  • SQL injection

Attack Mechanism

  • Small query with spoofed source IP
  • Large response sent to victim
  • Uses DNS resolvers as reflectors

Impact

  • DDoS amplification factor up to 54x
  • Overwhelms victim bandwidth

Mitigation

  • Disable recursion for external clients
  • Rate limiting
  • Response rate limiting (RRL)

Key Takeaways

  1. Network architecture provides the foundation for implementing security controls
  2. Different protocols have different security implications
  3. Defense strategies must consider threats at multiple layers
  4. Understanding network fundamentals is essential for effective security implementation

6. Firewalls & Intrusion Detection/Prevention Systems (IDPS)

Learning Objectives

  • Differentiate types of firewalls and their capabilities
  • Compare host-based vs. network-based IDPS
  • Understand signature-based vs. anomaly-based detection
  • Analyze deployment strategies for effective defense

Firewall Types Evolution

Stateful Firewall Operation

IDPS Fundamentals

Detection Methodologies

Signature-Based Detection

  • Matches patterns of known attacks
  • Low false positives
  • Cannot detect zero-day attacks

Anomaly-Based Detection

  • Identifies deviations from baseline
  • Can detect unknown attacks
  • Higher false positive rate

Evasion Techniques

  • Fragmentation:
    • Split packets to avoid detection
    • Overlapping fragments
  • Encryption/Tunneling:
    • Hide malicious content
    • Challenge for IDPS
  • Protocol Obfuscation:
    • Manipulate protocol fields
    • Unicode evasion
  • Low and Slow Attacks:
    • Stay below detection thresholds
    • Distributed attack sources

2013 Retail Breach

  • Incident: 2013 breach of 40 million credit cards
  • Attack Vector:
    • Initial compromise via HVAC vendor
    • Malware installed on POS systems
    • Data exfiltrated
  • Security Failures:
    • Firewall alerts ignored
    • Malware detection missed
    • Segregation insufficient
  • Lessons:
    • Importance of alert response
    • Need for defense in depth
    • Value of security monitoring

Key Takeaways

  1. Firewalls provide essential network traffic control and perimeter defense
  2. IDPS complement firewalls by detecting and potentially preventing attacks
  3. Detection methodologies must balance security with operational requirements
  4. Effective deployment requires consideration of performance, coverage, and response capabilities

VPN Fundamentals

VPN Protocol Comparison

Protocol Security Performance NAT Traversal Use Case

OpenVPN High Medium Good Remote access
SSTP High Medium Excellent Windows environments
IKEv2 High High Good Mobile devices
WireGuard High Very High Good Modern applications

Site-to-Site vs. Remote Access VPNs

Site-to-Site VPNs

  • Purpose: Connect entire networks
  • Architecture: VPN gateways at each site
  • Use Cases:
    • Branch office connectivity
    • Data center replication
    • Hybrid cloud connections

Remote Access VPNs

  • Purpose: Connect individual users
  • Architecture: VPN client to corporate gateway
  • Use Cases:
    • Teleworking
    • Business travel
    • Contractor access

VPN Security Challenges

  • Authentication Issues:
    • Weak credentials
    • Stolen certificates
    • Lack of MFA
  • Configuration Vulnerabilities:
    • Weak encryption algorithms
    • Improper firewall rules
    • DNS leaks
  • Endpoint Security:
    • Compromised client devices
    • Malware propagation through VPN
    • Unsecured networks on client side

Performance vs. Security Trade-offs

WireGuard

  • Modern cryptography
  • Small codebase
  • High performance

Zero Trust Network Access (ZTNA)

  • Identity-centric access
  • Granular permissions
  • Continuous verification

SD-WAN with Integrated Security

  • Application-aware routing
  • Integrated security functions
  • Centralized management

Challenge

  • Aging IPsec infrastructure
  • Performance issues
  • Difficult client management

Solution

  • Hybrid approach with IPsec for site-to-site
  • SSL VPN for remote access
  • Cloud-based security services

Results

  • Improved user experience
  • Simplified management
  • Enhanced security posture

Lessons

  • No one-size-fits-all solution
  • Migration planning is critical
  • User experience drives adoption

Key Takeaways

  1. VPNs provide essential secure connectivity over untrusted networks
  2. Protocol selection depends on security requirements, performance needs, and use cases
  3. Deployment models must address specific connectivity scenarios
  4. VPN security requires attention to configuration, authentication, and endpoint security

Glossary

Cryptography Terms

Symmetric Cryptography:
Encryption using the same key for both encryption and decryption
Asymmetric Cryptography:
Encryption using a public/private key pair
Hash Function:
One-way function that produces fixed-size output from variable input
Digital Signature:
Cryptographic mechanism for verifying authenticity and integrity
Key Exchange:
Process of securely sharing cryptographic keys
Non-repudiation:
Assurance that a party cannot deny the validity of a transaction

Network Security Terms

Firewall:
Network security system that monitors and controls traffic
Intrusion Detection System (IDS):
System that monitors for malicious activities
Intrusion Prevention System (IPS):
System that detects and prevents malicious activities
Virtual Private Network (VPN):
Secure connection over untrusted network
Demilitarized Zone (DMZ):
Network segment with controlled access to internal resources
Stateful Inspection:
Firewall capability to track connection states

Protocol Terms

TLS/SSL:
Protocol for secure communication over computer networks
IPsec:
Protocol suite for secure IP communications
DNSSEC:
Extensions to DNS for authenticating origin of data
PKI:
Framework for creating, managing, and revoking digital certificates
OCSP:
Protocol for checking revocation status of digital certificates
IKE:
Protocol for setting up security associations in IPsec
